NGINX Ingress Controller

The gold-standard, open-source Ingress controller maintained by the Kubernetes Community (kubernetes/ingress-nginx) and F5 NGINX.

1. Architecture & Mechanism

NGINX Ingress Controller deploys as a Kubernetes Pod (Deployment or DaemonSet) running an NGINX reverse proxy bundled with a Go-based controller loop. The controller watches Ingress resources and Endpoints in the cluster. It dynamically reconfigures NGINX routing tables via Lua shared memory dictionaries, avoiding full process reloads when backend pods scale up or down.

⚡ Regex & URL Rewrites

Unmatched power in path rewriting using regular expression captures (e.g. rewrite-target: /$2), stripping subpaths before forwarding to upstream backend applications.

🛡️ Traffic Shaping & Security

Supports IP whitelisting, basic authentication, rate-limiting (RPS/RPM), custom error pages, and external authentication via OAuth2/Keycloak.

2. Key Annotations & Ingress Example

A typical NGINX Ingress manifest featuring rewrite target and rate limiting:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nginx-sample-ingress
  annotations:
    kubernetes.io/ingress.class: "nginx"
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/limit-rps: "50"
    nginx.ingress.kubernetes.io/proxy-body-size: "20m"
spec:
  ingressClassName: nginx
  rules:
  - host: abc.jogeshwari.xyz
    http:
      paths:
      - path: /nginx
        pathType: Prefix
        backend:
          service:
            name: nginx-web-svc
            port:
              number: 80

3. Trade-offs (Pros & Cons)

Advantages:
  • Runs on any Kubernetes cluster (AWS EKS, Azure AKS, GCP GKE, Minikube, On-Prem).
  • Enormous community knowledge base and thousands of battle-tested examples.
  • Extensible with custom Lua scripts and Nginx configuration snippets.
  • Prometheus metrics exporter natively included for Grafana dashboards.
Considerations:
  • Consumes compute and memory from your worker node pool.
  • Heavy configuration changes on gigantic clusters can cause CPU spikes.
  • Requires careful tuning of buffer sizes and worker connections for extreme concurrency.
