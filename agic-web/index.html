Azure Application Gateway Ingress Controller

Azure Application Gateway Ingress Controller (AGIC)

A Kubernetes application that makes it possible for Azure Kubernetes Service (AKS) customers to leverage Azure's native Application Gateway L7 load balancer directly.

1. Architecture & Mechanism

AGIC monitors the AKS cluster's Kubernetes API server for changes to Ingress, Service, and Endpoint resources. When a change occurs, the AGIC pod translates those declarative Kubernetes manifests into Azure Resource Manager (ARM) REST API calls and applies the routing configuration directly to the Azure Application Gateway.

⚡ Direct Pod Routing (Azure CNI)

Unlike in-cluster reverse proxies, App Gateway routes traffic directly to AKS Pod private IPs via Azure CNI, completely bypassing NodePort translation and kube-proxy hops.

🛡️ Azure WAF Protection

Provides enterprise Web Application Firewall (OWASP CRS ruleset) at the network perimeter to defend against SQLi, XSS, and DDoS before malicious packets ever enter the cluster.

2. Key Annotations & Ingress Example

Here is how AGIC is configured using standard annotations:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: agic-sample-ingress
  annotations:
    kubernetes.io/ingress.class: azure/application-gateway
    appgw.ingress.kubernetes.io/backend-path-prefix: "/"
    appgw.ingress.kubernetes.io/ssl-redirect: "true"
    appgw.ingress.kubernetes.io/cookie-based-affinity: "true"
spec:
  ingressClassName: azure-application-gateway
  rules:
  - host: abc.jogeshwari.xyz
    http:
      paths:
      - path: /agic
        pathType: Prefix
        backend:
          service:
            name: agic-web-svc
            port:
              number: 80

3. Trade-offs (Pros & Cons)

Advantages:
  • No data-plane CPU/Memory consumption inside cluster worker nodes.
  • Managed PaaS scaling, 99.95% SLA, and automatic patching.
  • Direct integration with Azure Key Vault for TLS certificate rotation.
  • Integrated Azure Monitor metrics and traffic analytics.
Considerations:
  • Tied directly to the Microsoft Azure cloud ecosystem (no on-prem).
  • Configuration updates take 10-30s via ARM API compared to instant in-cluster reloads.
  • Requires Azure CNI or Kubenet with advanced routing setup.
