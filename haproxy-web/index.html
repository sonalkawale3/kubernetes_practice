HAProxy Ingress Controller

HAProxy Ingress Controller

Renowned for world-class raw throughput, microsecond request latency, and hitless dynamic configuration reloads under immense load.

1. Architecture & Mechanism

The HAProxy Ingress controller runs an optimized HAProxy event-driven proxy engine alongside a Kubernetes controller daemon. Rather than reloading the daemon whenever pod endpoints change, HAProxy communicates with an in-memory Runtime Socket API to dynamically add, remove, and health-check backend servers in microseconds without process restarts.

⚡ Hitless Dynamic Reloads

Dynamically updates upstream server states and slot allocations through runtime sockets without dropping existing TCP sockets or leaking file descriptors.

🛡️ Advanced DDoS & Rate Limiting

Engineered to handle SYN floods, Slowloris attacks, and extreme volumetric spikes using stick tables to track client request velocities with near-zero latency penalty.

2. Key Annotations & Ingress Example

HAProxy Ingress manifest configuration example:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: haproxy-sample-ingress
  annotations:
    kubernetes.io/ingress.class: "haproxy"
    haproxy.org/rewrite-target: /
    haproxy.org/ssl-redirect: "true"
    haproxy.org/load-balance: "roundrobin"
    haproxy.org/rate-limit-requests: "100"
spec:
  ingressClassName: haproxy
  rules:
  - host: abc.jogeshwari.xyz
    http:
      paths:
      - path: /haproxy
        pathType: Prefix
        backend:
          service:
            name: haproxy-web-svc
            port:
              number: 80

3. Trade-offs (Pros & Cons)

Advantages:
  • Industry-leading speed, memory efficiency, and ultra-low CPU consumption.
  • Zero connection drops during high pod churning due to runtime socket reloads.
  • Sophisticated cookie-based sticky sessions and active health checking.
  • Rock-solid defense against DDoS and malicious crawler patterns.
Considerations:
  • Smaller community extension ecosystem compared to NGINX.
  • Custom header manipulation syntax is slightly more specialized.
  • Typically chosen when throughput and latency are the #1 architectural priority.
